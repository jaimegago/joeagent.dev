{{/* 1. What Joe is, in one sentence. */}}
Kubernetes AI copilot

A Kubernetes AI copilot you run locally, with your own LLM key.

Joe Operates Everything. It investigates clusters, diagnoses problems, and drafts changes — applying them when you ask. It runs on your own machine and talks to your model provider directly.

{{/* 2. Two-binary distribution model. */}}
Two binaries

A clean client/server split. The CLI stays thin; all the agent logic lives in the server.

joe CLI

The thin client. It talks to joe-core over a local API and stays out of the way — no agent logic ships here.

joe-core server

The server. It hosts the agentic runtime and serves an embedded React UI compiled into the binary with go:embed — one file, no asset directory to deploy.

{{/* 3. Security model highlights. */}}
Security model

Joe is built to operate inside boundaries, not around them.

Zones
Explicit boundaries that scope what Joe is allowed to reach. Access is granted per zone, not all at once.
RBAC middleware
Every action passes through role-based access control before it runs. Permission is checked at the boundary, in code.
MCP server
Capabilities are exposed over the Model Context Protocol — tools are declared, typed, and inspectable.
Local tool execution
Tools execute on your machine, inside Joe — not in a vendor cloud. The execution boundary stays local.
{{/* 4. OASIS evaluation — prominent. */}}
Evaluated end-to-end

Tested against the OASIS Software Infrastructure profile

Joe has been evaluated end-to-end against OASIS — the open standard for testing whether an autonomous agent stays inside its rules. Binary safety gates, no “mostly safe” tier, and independent verification of the actual system state. No LLM in the verification loop.
